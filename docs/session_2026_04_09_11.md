### 2. Diagnosed OuteTTS Model Version Mismatch

The CUDA assertion error `indexSelectSmallIndex: srcIndex < srcSelectDimSize`
indicated that the OuteTTS-0.3-500M model was generating token IDs outside the
vocabulary bounds of the DAC codec in outetts 0.4.4.

Investigation of `outetts.Models` enum revealed available versions:
```
VERSION_0_1_SIZE_350M, VERSION_0_2_SIZE_500M, VERSION_0_3_SIZE_1B,
VERSION_0_3_SIZE_500M, VERSION_1_0_SIZE_0_6B, VERSION_1_0_SIZE_1B
```

The v0.3 models use an older codec incompatible with library v0.4.4.
The v1.0 models are designed for the current library version.

### 3. Researched OuteTTS 1.0 0.6B

Key findings:
- **HuggingFace ID**: `OuteAI/OuteTTS-1.0-0.6B`
- **Architecture**: Qwen3 0.6B backbone (continued pre-training + fine-tuning)
- **Language support**: 14 languages including **Spanish** (trained on MLS + Common Voice)
- **API change**: v1.0 requires `InterfaceVersion.V3` and `Backend.HF`. The
  recommended approach is `ModelConfig.auto_config()` which handles this
  automatically.
- **Sampling**: Same parameters work (temp=0.4, top_k=40, top_p=0.9, rep_penalty=1.1).
  Repetition penalty applied to 64-token recent window only (library handles this).
- **License**: Apache 2.0

### 5. Checkpoint/Resume Logic Added to Step 3 (All 3 Pipelines)

Production runs generate 810 samples (162 speakers x 5 texts). A crash at
sample 400 would lose all progress because `generation_metadata.json` was
written once at the very end. This was a critical design flaw.

**Fix applied to Chatterbox, OpenVoice, and OuteTTS step_03 files:**

1. **Load existing checkpoint**: at the start of `execute()`, if
   `generation_metadata.json` already exists, load it as the starting
   `generated` dict.
2. **Skip cached samples**: before generating each sample, check if
   `sample_id` is already in the loaded metadata AND the `.wav` file exists
   on disk. If both true, skip.
3. **Incremental save**: after every single successful generation, write the
   full metadata JSON to disk immediately (~10ms overhead vs seconds-to-minutes
   per generation).
4. **Speaker-level skip** (OpenVoice + OuteTTS only): if ALL samples for a
   speaker are already cached, skip the expensive speaker embedding extraction
   / profile creation entirely.

**How to verify checkpoint/resume works:**

```bash
# 1. Start production
export CUDA_VISIBLE_DEVICES=1
source ~/ANTI-SPOOFING-VOICE-LATIN-AMERICA/envs/chatterbox_env/bin/activate
cd ~/ANTI-SPOOFING-VOICE-LATIN-AMERICA
python -m app.pipeline.chatterbox_attack.pipeline_facade

# 2. Wait for ~5-10 "Generated arf_..." lines in Step 3, then Ctrl+C

# 3. Restart the same command:
python -m app.pipeline.chatterbox_attack.pipeline_facade

# 4. Look for in the logs:
#    "Resuming from checkpoint: N samples already generated"
#    "Generating 810 synthetic samples (N cached)..."
#    Progress bar jumps past cached samples instantly, resumes at N+1
```

If it says "Resuming from checkpoint: 0" or re-generates existing samples,
the checkpoint logic is broken and must be fixed before launching long runs.

**Note**: FishGram and Qwen do NOT have this fix (production already complete,
not worth risking changes to finished pipelines).
