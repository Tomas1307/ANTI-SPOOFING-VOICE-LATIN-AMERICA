# Decision Log

**Status:** Active
**Last updated:** 2026-06-09

Chronological record of architectural, methodological, and research decisions.

---

### 2026-02-17: TTS System Selection
**Context:** Needed to select TTS systems for generating synthetic Spanish voice attacks.
**Decision:** 6 systems: Fish Speech (primary), Qwen3-TTS, OpenVoice, Chatterbox, OuteTTS, CosyVoice.
**Alternatives considered:** XTTS, Bark, Parler-TTS. Rejected for poor Spanish support or discontinued development.
**Outcome:** CosyVoice later dropped (generates Chinese for Spanish input). 5 systems in production.

### 2026-03-15: HABLA v2 over v1 for bonafide corpus
**Context:** Original HABLA v1 had 162 speakers. v2 expanded to 1,567 speakers across 7 Latin American accents.
**Decision:** Use v2 exclusively. Update all pipeline BONAFIDE_DIR references.
**Alternatives considered:** Keep v1 for faster iteration. Rejected: v1 lacks accent diversity.
**Outcome:** All 5 attack pipelines use v2. ~35,927 bonafide samples as target.

### 2026-03-20: 1:1 Bonafide Matching (MATCH_BONAFIDE_COUNT=True)
**Context:** Each speaker has variable bonafide counts. Generate exactly as many attack samples as bonafide per speaker.
**Decision:** MATCH_BONAFIDE_COUNT=True in all pipelines. ~35,927 total attack samples per TTS system.
**Alternatives considered:** Fixed N per speaker, or all combinations. Rejected: unbalanced dataset harms detector training.
**Outcome:** Consistent ~35k samples per pipeline. Balanced bonafide:spoof ratio.

### 2026-04-07: Full-sentence cloning for partial spoof (not word-by-word)
**Context:** Need to extract individual words from TTS clone for partial spoof. Two options: generate each word separately, or generate full sentence and extract.
**Decision:** Clone the full sentence, then extract words via forced alignment.
**Alternatives considered:** Word-by-word generation. Rejected: isolated words have flat, citation-form prosody that is trivially detectable.
**Outcome:** Natural in-context prosody preserved. Harder for detectors. But creates the alignment accuracy challenge.

### 2026-04-10: Text-matching splice engine (not positional index)
**Context:** Original splice engine used `cloned_words[idx]` positional matching. If clone has fewer/different words, wrong content gets spliced.
**Decision:** Build text lookup map with NFKD normalization for Spanish accents. Match by word text, not position.
**Alternatives considered:** Strict positional matching. Rejected: fails when TTS drops/merges words.
**Outcome:** 33/33 Spanish character pairs pass normalization. Handles Como/Cómo, niños/ninos, etc.

### 2026-04-15: Non-adjacency constraint for word selection
**Context:** Replacing adjacent words creates a contiguous spoofed block that is easy to detect and sounds unnatural.
**Decision:** Selected word indices must differ by >= 2. Enforced via rejection sampling.
**Alternatives considered:** No constraint (random). Rejected: contiguous blocks are a trivial forensic shortcut.
**Outcome:** W1=1 word, W2=2 non-adjacent, W3=3 non-adjacent. Forces detectors to find scattered replacements.

### 2026-04-22: 7 crossfade techniques with weighted random selection
**Context:** Literature uses varied splicing methods. LlamaPartialSpoof uses 5 fade shapes. We wanted diversity.
**Decision:** 7 techniques: cut-paste (10%), OLA Hanning (20%), linear (15%), cosine (20%), half-sine (15%), logarithmic (10%), parabola (10%). Per-splice random draw.
**Alternatives considered:** Single technique (Hann only). Rejected: detector learns one fingerprint.
**Outcome:** Implemented, but listening tests revealed the technique doesn't matter audibly — the real problem was elsewhere. See 2026-04-25 decisions.

### 2026-04-25: Valley-score word selection (replacing random selection)
**Context:** Listening tests showed all 7 crossfade techniques sounded identical. The audible problem was: (a) words selected at boundaries with no energy valley in the clone, (b) duration mismatch shifting speech rhythm by 100-200ms.
**Decision:** Replace random word selection with energy valley scoring. For each word boundary, `score = min_rms / avg_rms` in +-100ms window. Only select words with deep valleys (score <= 0.65).
**Alternatives considered:** (a) Generate TTS with gaps between words (changes prosody), (b) Better forced aligner (doesn't exist for Spanish at word level). Valley score is a post-hoc filter that doesn't modify the generation.
**Outcome:** Testing. Expected to eliminate bad-sounding splices by only selecting words at clean boundaries.

### 2026-04-25: Clone similarity gate (ECAPA >= 0.60)
**Context:** Bad TTS clones go through the entire pipeline (Steps 3-5) wasting compute and producing obviously detectable splices.
**Decision:** Add ECAPA-TDNN cosine similarity gate between Steps 2 and 3. Reject clones with SIM < 0.60.
**Alternatives considered:** (a) Higher threshold 0.70 — rejects too many (FishGram avg is 0.602), (b) No gate — wastes compute on bad clones.
**Outcome:** Testing. Threshold 0.60 is configurable in settings.py.

### 2026-04-25: Duration-preserving splice (overwrite in place)
**Context:** Previous approach inserted cloned word at natural duration, changing total audio length. A 480ms clone replacing a 640ms bonafide slot shifted everything by 160ms, destroying speech rhythm.
**Decision:** Time-stretch cloned word to fit exact bonafide slot duration. Overwrite in place. Total length never changes.
**Alternatives considered:** (a) Keep natural duration (rhythm breaks), (b) Phase vocoder for higher quality stretch (complexity, marginal benefit for small ratios). Linear interpolation sufficient for ratios 0.75-1.25.
**Outcome:** Testing. All output audio should have identical duration to bonafide source.

### 2026-05-01: OmniVoice (k2-fsa) added as 6th attack pipeline
**Context:** Need an additional TTS attack vector with a fundamentally different architecture from the existing 5 (Fish Speech, Qwen3-TTS, OpenVoice, Chatterbox, OuteTTS). OmniVoice is a diffusion-language-model TTS supporting 646 languages with 27,559 hours of Spanish training data — one of the largest Spanish coverage among open zero-shot TTS models.
**Decision:** Implement `app/pipeline/omnivoice_attack/` following the canonical 5-step structure (prepare_references, prepare_texts, generate_speech, validate_quality, format_output). Use Python API (`OmniVoice.from_pretrained`) in-process; pre-compute reference text with Parakeet TDT (consistent with project STT stack); resample 24 kHz native to 16 kHz on FLAC write. Audio ID range = 15M+ (avoids collision with partial_spoof main W1/W2/W3 at 12-14M).
**Alternatives considered:** (a) HTTP API server like Fish Speech — rejected, OmniVoice in-process is simpler and Fish-style pattern only justified by Fish's heavy native dependencies. (b) Internal Whisper auto-transcription for ref_text — rejected, conflicts with "siempre Parakeet" rule and adds a 2nd ASR model. (c) torch 2.8.0+cu128 (upstream recommendation) — rejected, ml-server03 driver 560.35.03 maps to CUDA 12.6, so cu126 is the safe match.
**Outcome:** Pipeline written, isolated venv `envs/omnivoice_env/` with `omnivoice_requirements.txt`. First run pending on ml-server03 to validate Spanish quality. OmniVoice is intentionally NOT used as the boundary-jitter pilot precisely because its quality is unvalidated.

### 2026-05-01: Boundary jitter feature (Step 5b) for partial spoof
**Context:** The current partial_spoof splice produces detectable artifacts only at the 2 boundaries surrounding each cloned word. The other N-3 boundaries (bonafide-bonafide) are clean. Detectors trained on this distribution can learn the shortcut "the noisy boundary is the splice", as documented in Negroni et al. (2024) (6.16% EER on PartialSpoof with no training, purely spectral-dynamic-range analysis of the join) and the generalization-shortcut analysis in Muller (2024). Master Tomas's idea: apply the same kind of structural artifacts that the splice produces, to ALL internal boundaries (including the spoof one), so the splice no longer stands out.
**Decision:** Add Step 5b `BoundaryJitterApplier` running after Step 5 and before Step 6. For every internal word boundary, throw a coin with `JITTER_PROBABILITY = 0.5`. Heads -> uniformly pick one of three structural manipulations: (a) **truncate** [10-40 ms uniform] — cut a fragment from one side, mimics hard cut/paste; (b) **overlap** [30-80 ms uniform, Hanning fade] — sum left tail with right head, mimics OLA-Hanning crossfade; (c) **bleed** [20-60 ms uniform] — insert a fragment of one adjacent word into the other, mimics tail bleed. Tails -> leave natural. Spoof boundaries receive the same coin flip on top of the existing splice, so the distribution of "manipulations per boundary" is no longer 0 vs 1 but 0/1 (bonafide-bonafide) vs 1/2 (bonafide-spoof) — much harder to use as a signal.
**Alternatives considered:** (a) Channel/codec/RIR augmentation per word (my initial proposal) — rejected by Master Tomas, raises WER significantly and addresses a different threat model than what we want. (b) Apply to entire utterance uniformly (channel matching) — rejected, doesn't address the per-boundary detection signal. (c) Skip spoof boundaries (only manipulate bonafide-bonafide) — rejected, leaves the spoof boundary distinguishable as the only one with a coin-flip-zero-extra-manipulation distribution. (d) Stack multiple operations per boundary — rejected, risks audible chopped audio.
**Outcome:** Implemented. Magnitude ranges grounded: overlap matches LlamaPartialSpoof crossfade range exactly (literature); truncate stays below Spanish syllable nucleus duration (50-90 ms) to preserve intelligibility; bleed covers Spanish VOT (4-29 ms) plus consonant-vowel transition. Boundaries processed right-to-left to avoid invalidating earlier sample positions. Total length drift bounded; recorded per utterance.

### 2026-05-01: Per-speaker bonafide partition for jitter dataset (frases distintas)
**Context:** Master Tomas wanted the jitter dataset to use sentences disjoint from the main partial_spoof dataset, so the combined training pool covers more of the data distribution rather than duplicating utterances with two processings.
**Decision:** Add `BONAFIDE_FILE_PARTITION` setting ('main' or 'jitter') that controls which half of each speaker's bonafide files are used. Files are shuffled per-speaker with a deterministic seed (`BONAFIDE_PARTITION_SEED + sha256(speaker_id)`) and split 50/50; 'main' takes the first half, 'jitter' takes the second half. No speakers are discarded; speakers with only 1 file contribute to whichever partition the shuffle assigned.
**Alternatives considered:** (a) Use the same utterances in both — rejected by Master Tomas, no diversity gain. (b) Different speakers for each partition — rejected, would change the speaker distribution between datasets and break comparability. (c) Discard speakers with too few files — rejected by Master Tomas, "no descartar speakers".
**Outcome:** Implemented in `step_01_transcribe_bonafide._apply_partition`. Trade-off explicit: the jitter dataset is NOT a clean ablation of the main dataset (different inputs, different processing) but covers complementary utterances. A clean ablation experiment would require running both partitions with both processings (4 combinations) — out of scope for now.

### 2026-05-01: Qwen as boundary-jitter pilot, not OmniVoice
**Context:** When piloting a new dataset technique, conflating two unknowns ("does the technique work?" + "does the TTS produce clean clones?") makes the experiment uninterpretable.
**Decision:** Pilot the boundary jitter feature exclusively on Qwen3-TTS, which is already validated and has the highest mean ECAPA similarity (0.720). OmniVoice quality is unknown until its standalone TTS pipeline runs successfully on ml-server03. If jitter improves detector EER on Qwen-based partial_spoof, replicate to Chatterbox, OpenVoice, OuteTTS, FishGram. OmniVoice joins the jitter suite only after passing standalone validation.
**Alternatives considered:** Pilot on OmniVoice (would have been "free" since the new code path is identical) — rejected, because the experiment's signal would be lost in TTS-quality noise.
**Outcome:** `BONAFIDE_FILE_PARTITION` and `ENABLE_BOUNDARY_JITTER` are pipeline-system-agnostic; any of the 6 attack systems can be paired with jitter. First production run will be `attack_system="qwen"` with `BONAFIDE_FILE_PARTITION="jitter"` and `ENABLE_BOUNDARY_JITTER=True`.

### 2026-05-06: Reference end-cut is the actual root cause of OmniVoice prefix bleed (not per-speaker failure)
**Context:** The earlier non-verbal-prefix-detection + retry decision (see entry below) was based on a misdiagnosis. Initial analysis of the validation run that bled on `arf_00295` led to the conclusion that OmniVoice has a deterministic per-speaker failure mode tied to specific reference clips or speaker embeddings. After Master Tomas listened to `arf_00295_ref.wav` and reported "the final phrase was cut", the actual root cause was found in `app/pipeline/omnivoice_attack/utils/audio_concatenation.py`: the concatenation routine sliced the last bonafide file at the exact sample boundary needed to hit a 10 s target duration, landing the cut mid-word. The reference therefore ended abruptly, and OmniVoice's diffusion conditioning attempted to "complete" the cut-off pattern at the start of generation -- producing the reference-voice fragment we observed. The same bug exists in all 7 other attack pipelines but only affects OmniVoice because diffusion-LM is uniquely sensitive to abrupt-end conditioning (autoregressive and VQGAN backends tokenize/quantize the reference and don't extrapolate from its trailing edge).
**Decision:** Rewrite `concatenate_with_padding` to (1) stop at the last file that fits without overflowing 10 s instead of slicing mid-file, (2) snap to the nearest silent frame within +/- 1 s of target if a single file alone exceeds 10 s (edge case), (3) always append 200 ms trailing silence regardless of where the body ended, so the reference always ends on a clean silence boundary. Keep the non-verbal-prefix detector and retry loop as a defensive backstop in case future references still produce bleed.
**Alternatives considered:** (a) Per-speaker reference selection retry (try different bonafide files if generation fails) -- rejected, addresses the symptom not the cause and complicates Step 1. (b) Tighten WER ceiling -- rejected, the bleed is sub-syllabic and Parakeet does not transcribe it, so WER is blind. (c) Forced phoneme alignment (Wav2Vec2 CTC, MFA) for the absorbed-bleed case -- deferred, not currently observed. (d) Retrofit the same fix to the other 7 pipelines -- declined for now (see future-work entry in `methodology/attack-systems.md`); FishGram/Qwen/OpenVoice production runs are complete, Chatterbox/OuteTTS are mid-run, and we have no direct evidence the bug affects them.
**Outcome:** Validation re-run after the fix: 6/6 passed first attempt, zero non-verbal-prefix rejections, zero retries needed. arf_00295 -- which previously bled deterministically across 6 generation attempts -- now passes cleanly. All quality metrics improved (WER 0.0394 -> 0.0185, CER 0.0181 -> 0.0083, NISQA 4.53 -> 4.59, Speaker Sim 0.680 -> 0.696). The earlier "deterministic per-speaker failure mode" finding is retracted; arf_00295's behavior was a consequence of the buggy reference, not a property of the speaker. The detector + retry infrastructure remains in place as defense in depth.

### 2026-05-06: OmniVoice non-verbal prefix detection — reject + retry, not trim
**Context:** Validation of OmniVoice (6 samples) showed 2/6 samples (both from `arf_00295`) had a 200-600 ms reference voice fragment leading the audio. Parakeet TDT did not transcribe the bleed (sub-syllabic), so WER stayed at 0.0 and the existing `detect_prefix_trim_point` (Qwen-style hallucinated-word alignment) returned 0.0. The validator reported "Prefix trims: 0" while the audio was clearly contaminated. The artifact is acoustically valid voice from the same speaker — VAD cannot distinguish it from the prompt content.
**Decision:** Add a second detector `detect_nonverbal_prefix_artifact` to `app/utils/prefix_trimmer.py` that computes RMS dBFS of the audio interval `[0, word_timestamps[0].start]`. If pre-RMS exceeds `NONVERBAL_PREFIX_RMS_FLOOR_DB = -55.0`, mark the sample as **rejected** rather than trimming it in place. Wire OmniVoice into `app/runner/production_runner.py` (key "3") with a new `_execute_omnivoice` method that calls `_retry_rejected` (mirroring the Qwen and FishGram pattern), so rejected samples are regenerated up to `MAX_GENERATION_RETRIES = 5` rounds. Threshold is data-driven: empirically, OmniVoice artifacts measure -22 to -25 dB and clean samples sit at -120 dB silence floor — a -55 dB cut sits 30 dB above the artifact band and 65 dB below the silence band.
**Alternatives considered:** (a) Trim in place using `T_first` as the trim point — rejected, risks cutting natural Spanish vowel onset (e.g., `/e/` of "Eurídice"), no way to know the artifact's true end point. (b) Fixed unconditional 100 ms trim — rejected, too crude, false-positives on clean samples. (c) Forced phoneme alignment (Wav2Vec2 CTC, MFA) — rejected for now, adds another model and another env dependency; deferred until production data shows the absorbed-bleed case (where Parakeet absorbs the bleed into the first word's start time) is common enough to need it. (d) Tighten WER ceiling to catch bleed via downstream WER — rejected, TEXT_00002 had WER=0.0 even with audible bleed.
**Outcome:** Implemented in `prefix_trimmer.py`, `omnivoice_attack/settings.py`, `omnivoice_attack/schemas/validation_result.py`, `omnivoice_attack/steps/step_04_validate_quality.py`, `production_runner.py`. Validation re-run with 5 retry rounds: detector achieved 100% recall (12/12 bleed instances flagged across initial + 5 retry rounds on 2 samples). Both `arf_00295` samples bled deterministically across all 6 generation attempts — surfaces a model-level failure mode (likely tied to specific reference clips or the speaker's diffusion conditioning) that retries cannot fix. Reference-selection follow-up needed before production. Other 4 samples passed cleanly without retry. Detection scope is OmniVoice-only; not retrofitted to other 5 pipelines until evidence shows they exhibit the same artifact.

### 2026-05-20: 40/20/10/10/10/10 attack distribution for HABLA-Spoof corpus
**Context:** With six TTS attacks at our disposal, a uniform 1/6 split would have been the obvious default but ignores quality differences. OmniVoice is the strongest end-to-end performer (best NISQA at 4.59, fastest RTF ~0.025) and Qwen has the highest ECAPA similarity (0.720). The other four (FishGram, OpenVoice, Chatterbox, OuteTTS) are weaker on at least one axis. Treating them all equally would dilute the corpus around the weakest attacks and bias detector training toward easy-to-detect noise.
**Decision:** Weight the corpus 40% OmniVoice, 20% Qwen, 10% each for FishGram / OpenVoice / Chatterbox / OuteTTS. Weights configured in `settings.ATTACK_WEIGHTS` and consumed by the dispatch manifest. Sum = 1.0; enforced at ManifestGenerator construction.
**Alternatives considered:** (a) Uniform 1/6 = 16.7% per attack -- rejected, dilutes around weakest attacks. (b) Quality-weighted by inverse WER -- rejected, would give the worst attacks the largest share (opposite of intent). (c) Top-2-only (OmniVoice + Qwen at 50/50) -- rejected, loses splice-fingerprint diversity that the 7-technique splice engine generates per attack.
**Outcome:** Corpus marginal is the design parameter. Detector trained on this distribution sees a long tail of weaker clones (40% of attacks) plus a strong core (40% OmniVoice + 20% Qwen). Per-speaker probabilistic assignment converges to this marginal at the corpus level even when individual speakers have too few files to cover all six attacks.

### 2026-05-20: Probabilistic per-speaker attack assignment with deterministic seed
**Context:** Given the 40/20/10/10/10/10 weights, how to assign each bonafide file to exactly one attack? Two camps: (a) Largest Remainder (Hamilton method) per speaker -- guarantees per-speaker proportions match the weights as closely as integer rounding allows; (b) Probabilistic multinomial draw per file -- preserves the corpus marginal exactly under the law of large numbers but allows local skew.
**Decision:** Probabilistic per-speaker multinomial draw. For each speaker, build a seeded RNG from `ATTACK_ASSIGNMENT_SEED + sha256(speaker_id)[:4]`, then for each of the speaker's files in each partition draw one attack from `Multinomial(p=ATTACK_WEIGHTS)`.
**Alternatives considered:** (a) Largest Remainder per speaker -- rejected, low-file-count speakers with 6 files would produce a 2/1/1/1/1/0 split where one of the 10% attacks is dropped entirely; the corpus marginal would systematically over-represent the 40% attack. (b) Global shuffle and stride-slice -- rejected, loses per-speaker reproducibility; manifest re-generation would shuffle differently as soon as a new speaker is added. (c) Speaker-level assignment (all of a speaker's files go to one attack) -- rejected, kills accent representation diversity per attack.
**Outcome:** Implemented in `ManifestGenerator`. Audited via `ManifestSummary`: corpus-wide actual fractions match target weights to ~1% by construction (deterministic verification baked into the pre-flight). Small-file-count speakers may miss some attacks (mathematical inevitability with 6-way 40/20/10/10/10/10) but every speaker contributes to at least one attack -- the "all speakers must be used" constraint is satisfied at the speaker level, not per-attack.

### 2026-05-20: Manifest-driven dispatch with pre-flight CSV
**Context:** Coordinating 12 production runs (6 attacks x 2 partitions) requires a single source of truth for which bonafide file goes to which (attack, partition). The previous design had each pipeline run shuffle and slice independently, which made post-hoc audit of the corpus distribution painful and reproducibility fragile.
**Decision:** Pre-flight script (`app/scripts/generate_partial_spoof_manifest.py`) runs once on the full HABLA v2 corpus and writes `data/manifests/partial_spoof_plan.csv` with one row per eligible bonafide file: `(sample_key, speaker_id, audio_path, split, partition, attack, planned_tiers, word_count, bonafide_transcript)`. Each per-attack pipeline run loads the manifest via `ManifestLoader`, slices to its `(attack, partition)` cell, and processes only those files. Step 1 short-circuits Parakeet by reading the cached full transcripts produced alongside the manifest.
**Alternatives considered:** (a) Inline assignment per pipeline run (each pipeline shuffles its own slice) -- rejected by Master Tomas, harder to audit and breaks reproducibility when speakers are added or removed. (b) Hybrid (inline assignment + thin per-run audit log) -- rejected, reconstructs the manifest piecewise after the fact instead of having a single authority. (c) Database-backed dispatch (sqlite) -- rejected, overkill for a write-once corpus plan and adds a binary dependency.
**Outcome:** Implemented. Manifest summary (`partial_spoof_plan_summary.json`) reports target vs actual attack marginals, per-attack-per-partition cross-tabulation, speakers covering all attacks vs single-attack speakers, and per-tier potential output counts. Becomes Table N in the paper directly.

### 2026-05-20: Step 6 metrics-only mode (keep-bad-stuff principle)
**Context:** ASVspoof-tradition is to filter spoof samples by WER/NISQA/ECAPA thresholds, keeping only the "good" attacks. Master Tomas's argument against this: real-world attackers don't post-filter their output, and a detector trained only on quality-gated spoofs learns to detect clean attacks but may collapse on noisy ones. LlamaPartialSpoof (Luong et al. 2024) also includes "wild" outputs without quality filtering.
**Decision:** `ENABLE_STEP_6_REJECTION = False` by default. Step 6 still computes WER, CER, NISQA, ECAPA SIM, boundary metrics for every sample, but does NOT filter. Every sample receives a `quality_flag` label ('high' / 'medium' / 'low') based on threshold combinations; downstream training stratifies on the flag instead. Only STRUCTURAL failures are rejected -- zero spoofed words, missing audio files, audio load errors -- because those are not actual partial spoofs. The upstream clone similarity gate (ECAPA SIM >= 0.60 between Step 2 and Step 3) stays enabled: filters non-attacks (clones that don't resemble the speaker) but not low-quality attacks.
**Alternatives considered:** (a) Keep legacy WER/CER rejection -- rejected, biases corpus toward easy-to-detect samples. (b) Drop the clone similarity gate too -- considered but Master Tomas chose to keep it ("keep the metrics we have, leave 0.6 alone"). The gate is upstream of splicing and protects against splicing garbage into bonafide audio. (c) Threshold-driven downsampling per quality bucket -- deferred, the corpus tells us the natural quality distribution per attack; we should observe before we engineer.
**Outcome:** Implemented in `step_06_validate_splice.py` with `quality_flag` derived from WER <= 0.10 AND NISQA >= 4.0 AND ECAPA SIM >= 0.50 -> 'high'; WER <= 0.30 -> 'medium'; else 'low'. The OpenVoice slice (avg SIM 0.394) will likely under-fill behind the clone gate but the surviving samples still cover the full quality spectrum on the splice axis.

### 2026-05-20: Per-audio checkpointing and orchestrator-driven aggregation
**Context:** A 12-job production sweep over a multi-day wall-clock budget is going to be interrupted at least once (network glitch, GPU reschedule, manual pause). The previous design used JSON metadata files as natural checkpoints (presence of cloned_generation_metadata.json indicated completion) which lost work granularity inside a step. Master Tomas requested "save checkpoints every time an audio is generated".
**Decision:** Add `app/pipeline/partial_spoof/utils/checkpoint_manager.py` with an atomic per-(attack, partition) JSON state file (`.checkpoint.json`) written via tmp+os.replace after every successful WAV commit. Step 2 marks each clone in `state.cloned`; Step 5 marks each spliced WAV in `state.spliced`; Step 5b marks each jittered WAV in `state.jittered`. Generation errors record a `GenerationFailure` with retry count; samples exceeding `MAX_GENERATION_RETRIES = 3` are abandoned (not raised). The orchestrator (`app/runner/partial_spoof_orchestrator.py`) provides single-job, aggregate (corpus CSV concatenation), runbook (12-command shell printout), and status modes.
**Alternatives considered:** (a) SQLite-backed checkpoint -- rejected, adds dependency and concurrency complexity for write-once-then-read state. (b) Step-level checkpointing only (presence of cloned_generation_metadata.json) -- rejected, kept the same granularity issue Master Tomas explicitly flagged. (c) Filesystem stat as checkpoint (WAV file exists -> done) -- rejected, atomic write semantics are weaker than a single small JSON written through tmp+rename.
**Outcome:** Implemented. Crash semantics: a process kill mid-WAV-write produces an incomplete WAV (deleted on next run since checkpoint doesn't list it) but never corrupts the checkpoint (atomic rename). Resume idempotency: re-running a finished job is a no-op (all sample_keys are in `state.cloned` and `state.spliced`). Quality-failure retries are NOT supported at this layer -- by design, low-quality samples are kept in the corpus.

### 2026-05-24: Strategy -> Cloner refactor (one source of truth per attack)
**Context:** partial_spoof had its own duplicate cloning code in `app/pipeline/partial_spoof/strategies/*.py` (7 strategy files) that re-implemented per-attack what each standalone attack pipeline's Step 3 already did. The two versions drifted apart and produced 5 silent bugs caught only when partial_spoof's strategies were actually exercised in the validation sweep: OpenVoice strategy referenced non-existent `TONE_CONVERTER_CONFIG` settings (AttributeError crash 25s in), OuteTTS strategy referenced non-existent `OUTETTS_TEMPERATURE`/`OUTETTS_REPETITION_PENALTY`/`OUTETTS_MAX_LENGTH` settings, Chatterbox strategy had a half-correct SDPA patch (walked `dir()` instead of `named_modules()` and only set `_attn_implementation`), OmniVoice strategy missed the `language=` parameter on `model.generate()`, Qwen strategy hardcoded `x_vector_only_mode=True` instead of reading the settings field. Plus `partial_spoof/utils/audio_concatenation.py` had diverged from `omnivoice_attack/utils/audio_concatenation.py` for ~3 weeks after the OmniVoice end-of-reference fix landed only on the standalone side.
**Decision:** Eliminate the duplicate strategies. Add `app/pipeline/<attack>_attack/utils/cloner.py` per attack (6 files) with a `Cloner` class subclassing `app/utils/base_cloner.BaseCloner` (ABC with `load`, `prepare_speaker`, `clone_single`, `cleanup`). Both the standalone Step 3 and the partial_spoof Step 2 import from the same Cloner. Add `app/pipeline/partial_spoof/utils/cloner_dispatcher.py` that lazy-imports the right Cloner class per `attack_system` string so partial_spoof Step 2 only pulls in the SDK for the attack actually running in the current venv. ### 2026-05-24: Splice engine architectural rewrite (8 bugs in one session)
**Context:** Audit auditiva por Master Tomas revealó múltiples defectos en los WAVs producidos por el splice engine: la palabra spliceada se oía dos veces (cloned + bonafide residual), el cloned sonaba "cartoony/grueso" (pitch shifted), las palabras quedaban truncadas ("Luga-" en vez de "lugar"), y a veces se leían palabras adyacentes del cloned filtrándose en los bordes. Además el yield real del corpus era ~50% del esperado en validación por crashes silenciosos del splice attributíos a "no eligible words" cuando en realidad eran fallas internas no reportadas. Una jornada de análisis con cross-correlación del audio reveló OCHO bugs distintos en el splice engine, todos en el mismo módulo (`app/pipeline/partial_spoof/utils/splice_engine.py`) y archivos vecinos.
**Decision:** Rewrite el splice engine. Cambios estructurales:

1. **Step 3 alignment_metadata acumula entre rondas de regen** (antes sobreescribía, perdiendo alignments de samples spliceados en rondas previas). Mismo patrón aplicado a splice_metadata.json en Step 5.
2. **`splice_seed` enmascarado con `& ((1<<63)-1)`** para garantizar non-negative. Python `hash()` devuelve signed int64; `np.random.default_rng([negative, idx])` crashea con "expected non-negative integer". Este bug crashaba muchos W1/W3 silenciosamente, era la principal causa del low yield en Qwen/OuteTTS/FishGram.
3. **Energy refinement de boundaries** (nuevo `app/pipeline/partial_spoof/utils/energy_refiner.py`). Parakeet TDT drifts 100-300 ms en frases rápidas encadenadas ("la casa"); el refiner detecta speech segments por RMS y recoloca los bordes en la posición acústica real. Conservative gate: solo refina si Parakeet's centre cae en silencio (evidencia clara de drift), si está en speech trust Parakeet (evita fragmentar palabras con stop closures internos como 'algunas' -> '-unas').
4. **Valley snap asimétrico** (direction="earlier" para start, "later" para end). El symmetric snap podía mover boundaries INWARD y encoger el slot, dejando el bonafide word parcialmente fuera. Outward-only garantiza cobertura completa.
5. **Removida la time-stretch duration-preserving** (linear interp resampling shifted pitch -> "cartoony"). Cloned se inserta a su duración natural; el total audio duration varía. Cumulative offset trackea positions para W2/W3 splices múltiples.
6. **Crossfade en las costuras** (no dentro del slot). El cloned source se extiende `cf` samples a cada lado para que el fade caiga en TTS silence padding alrededor de la palabra, no en la palabra misma (evita "Luga-").
7. **Silent-run gate en la extension** (`_silent_run_backward/_forward`): la extensión del cloned source solo va hasta donde haya silencio real. Si la palabra siguiente/anterior del cloned está pegada, la extensión se acorta y el fade colapsa a CUT_PASTE de ese lado (evita leak de palabras vecinas).
8. **Step 2 / Step 3 metadata acumulan** (no sobreescriben en regen rounds). El Step 3 fix ya estaba parcialmente; lo extiendo a Step 5 splice_metadata.

**Alternatives considered:** (a) Subir `MAX_STRETCH_RATIO` a 1.5x o 2.0x -- rejected, los artefactos cartoony aparecían ya desde 1.10x. (b) Phase vocoder (`librosa.effects.time_stretch`) preservando pitch -- implementado intermedio pero superado por la decisión de eliminar time-stretch entirely. (c) Mantener duration-preserving y aceptar artefactos cartoony -- rejected por Master Tomas (audit auditiva); no es necesario porque el corpus partial_spoof solo se usa con per-word labels, NO contra el bonafide original. (d) Refinar solo bonafide y dejar cloned con Parakeet -- considerado, pero TTS clones también tienen drift menor en algunos casos; el conservative gate hace que solo refine cuando hay evidencia clara, aplicable a ambos lados.
**Outcome:** Validation 2026-05-24 lanzada después del fix. Total tiempo: 1h 8min (vs. 2-3h previas con crashes intermedios). Yields doblaron: omnivoice 81 -> 169, qwen 6 -> 25, fishgram 19 -> 30, chatterbox 41 -> 62, outetts 4 -> 9, openvoice 0 -> 0 (gate SIM 0.60 sigue rechazando todo, esperado). Total: 151 -> 295 samples (1.95x). Cero "Alignment missing", cero "expected non-negative integer" en los 12 logs. Audit auditiva Master Tomas: aprobó calidad ("Si me parecio bien").

Nueva arquitectura registrada en `memory/splice_engine_lessons.md`. Settings finales: `CROSSFADE_MIN_MS=30, CROSSFADE_MAX_MS=80` (sin cambio), `VALLEY_SEARCH_MS=50`, `ENERGY_REFINE_RADIUS_S=0.300`, `ENERGY_REFINE_SILENCE_RMS=0.015`, `min_segment_dur_ratio=0.40`, `merge_gap_ms=60`. ### 2026-05-30: Per-file voiced-RMS loudness matching for spoof words
**Context:** Audit auditiva por Master Tomas: las palabras spliceadas (spoof) a veces se oyen mas fuertes o mas suaves en decibeles que el bonafide circundante del mismo clip. Existia ya un matching por palabra (`normalize_energy` en `crossfade.py`) llamado desde ambas ramas del splice engine, pero el bug estaba en la REFERENCIA: el RMS bonafide se medía sobre `result[b_start:b_end]`, el slot reemplazado, cuyos bordes son valley-snapped HACIA AFUERA dentro del silencio inter-palabra (`find_nearest_valley` direction earlier/later). Asi la referencia promediaba palabra+silencio (deflactada) mientras el lado cloned se medía word-only -> las palabras spoof quedaban sistematicamente demasiado suaves. Riesgo metodologico: un offset de loudness spoof-vs-bonafide es un atajo trivial ("loud = spoof") que el detector puede aprender en vez del artefacto real de spoofing.
**Decision:** Reemplazar `normalize_energy` por un modulo nuevo `app/pipeline/partial_spoof/utils/loudness.py` (3 free functions: `compute_voiced_rms`, `scale_to_reference_rms`, `apply_peak_ceiling`). Estrategia LOCAL per-file (no objetivo global de dB fijo, que solo seria seguro si el bonafide se normalizara igual): se calcula UN ancla de voiced-RMS por utterance sobre el bonafide host ORIGINAL (una vez por llamada a `splice_words`, antes de cualquier splice -> independiente de `cumulative_offset`), midiendo solo frames vocalizados (gate adaptativo `max(ENERGY_REFINE_SILENCE_RMS, 0.15*P95(frame_rms))`), y se escala cada palabra cloned a esa ancla. Ambas ramas (CUT_PASTE y crossfade) usan el mismo helper (DRY: antes duplicaban el ratio RMS); la rama crossfade reutiliza la ganancia devuelta para escalar el padding y mantener costuras suaves. Metrica RMS lineal (= RMS-dB), sin LUFS/pyloudnorm (palabras <400 ms, gating LUFS ~400 ms no es fiable). Guarda de pico (`apply_peak_ceiling`, ceiling 0.99) en Step 5 antes de `sf.write` porque Step 7 exporta FLAC PCM_16 (entero) que hace hard-clip >1.0. Nuevos settings: `LOUDNESS_MATCH_ENABLED=True`, `LOUDNESS_REFERENCE_MODE="utterance"`, `LOUDNESS_VOICED_FRAME_MS=20.0`, `LOUDNESS_VOICED_GATE_FRACTION=0.15`, `LOUDNESS_PEAK_CEILING=0.99`. `splice_details` ahora registra `loudness_target_rms` y `loudness_applied_scale` para trazabilidad.
**Alternatives considered:** (a) Normalizacion global per-file (escalar todo el archivo a un objetivo) -- rejected, no corrige el mismatch DENTRO del archivo (preserva la razon spoof/vecino). (b) Objetivo corpus-wide de dB fijo (p.ej. -23 LUFS) -- rejected, introduce el artefacto asimetrico "loudness constante = spoof" si el bonafide eval no se normaliza igual. (c) Referencia = slot reemplazado con gate de silencio -- considerado como `LOUDNESS_REFERENCE_MODE` futuro, pero alta varianza en palabras <400 ms; "utterance" garantiza ademas consistencia W2/W3. (d) LUFS via pyloudnorm -- rejected (dep nueva + gating no fiable en palabras cortas).
**Outcome:** Implementado (5 archivos: nuevo `loudness.py`; `crossfade.py` borra `normalize_energy`; `splice_engine.py` swap import + 4 kwargs + ancla; `settings.py` +5 Fields; `step_05_splice_audio.py` pasa kwargs + peak guard). Test de verificacion CPU-only en `app/tests/test_loudness_matching.py` (audio sintetico): asserta spoof voiced-RMS dentro de +/-1.5 dB del ancla en ambas ramas, ablacion disabled queda mas suave, all-silence host no crashea (scale 1.0), modo desconocido lanza ValueError. Pendiente: correr el test y re-correr Step 5 en slice de validacion en ml-server03, audit auditiva, luego re-run completo del corpus.

**Refinamiento 2026-05-30 (overshoot +2.4 dB):** primera validacion en ml-server03 (qwen/not_jittered, 14 samples via `scripts/check_loudness_match.py`) dio spoof-vs-bonafide delta mean +2.37 dB / median +2.15 / p90 4.27, solo 36% dentro de +/-1.5 dB (peak 0.990, sin clipping -> el ceiling funciono). Causa: asimetria de medicion. El ancla bonafide es voiced-RMS (silence-gated) pero el clon se escalaba por su PLAIN RMS (`scale_to_reference_rms`, full-segment). Plain RMS < voiced RMS por el silencio intra-palabra, asi que para llevar el plain del clon al ancla voiced, su contenido voiced sobrepasaba el ancla -> spoof ~2.4 dB mas fuerte. El unit test sintetico no lo detecto porque un tono puro no tiene silencio intra-palabra (plain == voiced). Fix: nueva `voiced_match_gain` mide el clon con el MISMO voiced-RMS gated que el ancla (apples-to-apples); `scale_to_reference_rms` eliminada (dead). Ambas ramas del engine y el unit test (clon con gap de silencio intra-palabra) actualizados. **Resuelto 2026-05-30:** re-splice (12 cells, parallel) + re-check qwen/not_jittered (14 samples): delta mean -0.06 dB / median -0.08 / abs-p90 0.74, 100% dentro de +/-1.5 dB, peak 0.824 (ceiling no necesario). ### 2026-06-01: Acoustic augmentation pipeline design — CODEC layer redesign
**Context:** The existing codec_augmenter.py used four independent Bernoulli gates (downsample, bandpass, packet loss, quantization) with no real codec applied. ### 2026-08-01: Augmentation input discovery rewritten after two silent-loss bugs (MP3 + dev/eval naming)
**Context:** First real 2x augmentation over the speaker-disjoint MARSA partition produced empty dev/eval (loader looked for legacy `val`/`test` directory names and misread the partition's top-level `train`/`dev`/`eval` folders as "3 speakers"), and after that fix the class ratio came out 90/10 when the corpus is actually ~85/15. Root cause: `_get_audio_files_recursive` filtered on `.wav`/`.flac` only, silently dropping every `.mp3` -- and 100% of dropped files were bonafide (13,111 of 35,927 = 36.5%; per split 10,160/1,871/1,080).
**Decision:** Collapse the triplicated per-split discovery into one `_discover_split_files()` path; accept `.mp3`; sort speakers by ID (filesystem order broke seed reproducibility); add `DatasetDiscoveryReport` (every file on disk is ingested or counted by extension -- silent drops structurally impossible); add `AugmentationPipeline._preflight_check()` that aborts before writing anything if any split is empty, any file was ignored, any filename matches neither class prefix, or any extension fails an actual decode probe.
**Alternatives considered:** Point-fix the extension tuple only (rejected: the triplication is why two bugs survived earlier fixes); convert mp3 to flac at partition build (rejected: librosa decodes mp3 natively, no need).

### 2026-08-02: Codec set finalized -- AAC container fix, AMR-NB via pinned static ffmpeg, iLBC replaced by Speex
**Context:** The realized 2x codec mix showed only 3 of 6 configured codecs (G.711u/a + Opus at renormalized 61.3/38.7). A bare `except Exception: return None` in `apply_codec` made a wrong encoder name indistinguishable from a missing codec. Diagnosis per codec: AAC failed on read-back because `codec_format="adts"` is a write-only muxer (ffmpeg's demuxer is named `aac`) -- our bug, not the environment; AMR-NB had a wrong encoder name (`amr_nb` is a codec ID; the encoder is `libopencore_amrnb`) AND is absent from Ubuntu's stock ffmpeg (licensing); iLBC requires `libilbc`, absent from stock Ubuntu ffmpeg AND both major static builds (johnvansickle 7.0.2, BtbN latest).
**Decision:** (1) AAC container changed to `mpegts` (verified round-trip both directions). (2) `CodecSpec` gains a `backend` field: `torio` (in-process AudioEffector) vs `ffmpeg_bin` (subprocess to the binary named by env var `MARSA_FFMPEG_BINARY`; pinned to `tools/ffmpeg-7.0.2-amd64-static/ffmpeg`, ~41 ms per AMR-NB round-trip). (3) iLBC replaced by **Speex** (`libspeex`, in stock build, runs in-process): same legacy-VoIP design slot (RFC 6716 positions Opus as Speex's successor), same CELP narrowband 8 kHz profile, same 0.05 weight. (4) Per-codec failures recorded via `get_codec_errors()`; preflight logs the enabled set and ABORTS if any codec is unavailable.
**Alternatives considered:** Ship 5 codecs without iLBC replacement (rejected: replacement keeps the six-slot design intact with near-identical justification prose); compile ffmpeg+libilbc from source (rejected: breaks corpus reproducibility -- the recipe should regenerate on a standard ffmpeg install; disproportionate for a 0.05-weight retired codec); substitute G.722/GSM (rejected: needs new justification research; Speex inherits iLBC's verbatim).
**Outcome:** All 6 probe OK on ml-server03. Rerun realized mix within 0.2pp of every target: G711u 24.8/25, G711a 14.9/15, AMR-NB 20.1/20, Speex 5.1/5, Opus 24.9/25, AAC 10.1/10. Spectral verification: AMR-NB/Speex clips have ~0.0000 energy above 4 kHz (true 8 kHz band-limiting) vs 0.0109 clean -- codecs genuinely applied, not passthrough.

### 2026-08-02: Metadata leak audit -- shuffled audio IDs, ID-sorted protocol rows, uniform mtimes
**Context:** Full leak audit requested before regenerating. Clips are emitted class-by-class (bonafide then spoof; clean before augmented within class), so two metadata channels encoded the label despite opaque filenames: (1) sequential audio IDs -- verified on the 2x corpus: bonafide = LA_T_0000001..0054266, spoof = 0054267..0358380, zero interleaving, a near-perfect class predictor; (2) file mtimes follow emission order, so `ls -t` yields a class-sorted listing and tar preserves it into a released archive.
**Decision:** Audio IDs drawn from a per-split pool shuffled with the seeded RNG (`_prepare_audio_ids`; pool exhaustion raises); protocol/metadata rows sorted by audio ID at write time (row position otherwise still leaks); `_normalize_timestamps()` stamps every emitted file with constant `CORPUS_MTIME` (2026-01-01 UTC) after the run.
**Alternatives considered:** Interleaved emission order (rejected: complicates the emit loops and still leaks through residual patterns; shuffling identity is cleaner than shuffling order).
**Outcome:** Channels audited clean in the same pass: loudness (verified -23.00 dBFS mean/min/max on 600 sampled outputs), duration (length-preserving round-trips), per-class clean fraction (equal by construction), aug-type assignment (label never in scope of any augmenter), protocol-to-file 1:1 (358,380 exact both directions), speaker disjointness on output (0 overlap all pairs), unique audio IDs (417,405/417,405). Documented-not-fixable: MP3 channel provenance (see next entry).

### 2026-08-02: Protocol format -- byte-faithful ASVspoof2019 LA + companion MARSA metadata CSV; slugs not A-codes
**Context:** Augmented protocols previously used the ASVspoof SYSTEM_ID column for the augmentation label, destroying attack attribution (a paper contribution) in the training corpus; and Master Tomas required the released protocol be the exact ASVspoof2019 format (verified online: real LA files are FIVE whitespace fields `SPEAKER AUDIO_ID - ATTACK_ID KEY`, the literal `-` third field being the PA environment slot; AASIST's genSpoof_list parses exactly this).
**Decision:** Two files per split: `ASVspoof2019.LA.cm.<split>.{trn,trl}.txt` in the exact 5-field format with ATTACK_ID = readable system slug (`fishgram`, `omnivoice-psw2`, `-` for bonafide), and `MARSA.LA.cm.<split>.metadata.csv` (`audio_id,speaker_id,key,attack_id,aug_id`) carrying the augmentation label the strict format has no field for. Attack IDs parsed from partition filenames by `DatasetLoader._attack_id()`. Slugs kept over A01-A19 codes: ASVspoof's opacity was blind-challenge anti-cheating, whereas MARSA's contribution is open attribution; parsers treat the field as an opaque string either way.
**Alternatives considered:** Augmentation label in the unused third field (rejected: byte-exact LA format required); A-code mapping (deferred: a ten-minute rename plus README table if a reviewer demands it).
**Outcome:** Since all six systems appear in every split (spoof follows its target speaker), the attack column enables user-constructed leave-one-system-out protocols -- the canonical split measures seen-attack detection only, and LOSO is the documented answer to that limitation (addresses the "authors leak" concern).
