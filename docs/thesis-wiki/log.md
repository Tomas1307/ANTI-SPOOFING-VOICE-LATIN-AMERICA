- **2026-05-06** — **Root cause of OmniVoice prefix bleed identified and fixed.** Master Tomas listened to `arf_00295_ref.wav` and reported the final phrase was cut. Investigation revealed the bug in `app/pipeline/omnivoice_attack/utils/audio_concatenation.py`: the routine sliced the last bonafide file at the exact sample boundary needed to hit a 10 s target duration, landing the cut mid-word. OmniVoice's diffusion conditioning attempted to "complete" the cut-off pattern at the start of generation -- which is the bleed we observed. The same bug exists in all 7 other attack pipelines but only OmniVoice is affected because diffusion-LM is uniquely sensitive to abrupt-end conditioning. Fix: stop at last fitting file (never slice mid-file), snap to nearest silence in edge case (single file > 10 s), always append 200 ms trailing silence. Post-fix validation: 6/6 PASSED first attempt, zero non-verbal-prefix rejections, zero retries needed; arf_00295 now passes cleanly. All metrics improved (WER 0.0394 -> 0.0185, CER 0.0181 -> 0.0083, NISQA 4.53 -> 4.59, ECAPA SIM 0.680 -> 0.696). Earlier "deterministic per-speaker failure mode" finding is retracted -- arf_00295's behavior was a consequence of the buggy reference, not a property of the speaker. The non-verbal-prefix detector + retry loop are kept as defense in depth. - **2026-06-08** — **Data-augmentation pipeline audited; new methodology page + Option B decided.** Read the full augmentation codebase (`app/augmenter/` base+RIR+Codec+RawBoost, `augmentation_config.py`, `schema.py`, `utils.py`, `augmentation_calculator.py`, `augmentation_pipeline.py`).
