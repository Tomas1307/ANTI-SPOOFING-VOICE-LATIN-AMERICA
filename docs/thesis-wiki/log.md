- **2026-05-06** — **Root cause of OmniVoice prefix bleed identified and fixed.** Master Tomas listened to `arf_00295_ref.wav` and reported the final phrase was cut. Investigation revealed the bug in `app/pipeline/omnivoice_attack/utils/audio_concatenation.py`: the routine sliced the last bonafide file at the exact sample boundary needed to hit a 10 s target duration, landing the cut mid-word. OmniVoice's diffusion conditioning attempted to "complete" the cut-off pattern at the start of generation -- which is the bleed we observed. The same bug exists in all 7 other attack pipelines but only OmniVoice is affected because diffusion-LM is uniquely sensitive to abrupt-end conditioning. Fix: stop at last fitting file (never slice mid-file), snap to nearest silence in edge case (single file > 10 s), always append 200 ms trailing silence. Post-fix validation: 6/6 PASSED first attempt, zero non-verbal-prefix rejections, zero retries needed; arf_00295 now passes cleanly. All metrics improved (WER 0.0394 -> 0.0185, CER 0.0181 -> 0.0083, NISQA 4.53 -> 4.59, ECAPA SIM 0.680 -> 0.696). Earlier "deterministic per-speaker failure mode" finding is retracted -- arf_00295's behavior was a consequence of the buggy reference, not a property of the speaker. The non-verbal-prefix detector + retry loop are kept as defense in depth. Wiki: attack-systems.md "OmniVoice prefix-bleed handling" rewritten with corrected story, new "Future improvement: retrofit fix to other pipelines" subsection added; decision-log.md gained the corrected root-cause entry; validation-results.md gained a three-stage timeline (initial / detector / post-fix); production-runs.md updated with post-fix metrics.

- **2026-05-24** — **Splice engine architectural rewrite** (8 bugs in one audit session). (1) Step 3 alignment_metadata and Step 5 splice_metadata now accumulate across regen rounds (previous overwrite cost samples in W1/W3 retry rounds). (2) `splice_seed = (settings.RANDOM_SEED + hash(key)) & ((1<<63)-1)` to mask sign bit (negative `hash()` was crashing `np.random.default_rng` with "expected non-negative integer", silently rejecting many W1/W3 splices). (3) New `app/pipeline/partial_spoof/utils/energy_refiner.py` corrects Parakeet drift on phrase-merged words like "la casa"; conservative gate (only refine if Parakeet centre falls in silence) prevents fragmentation of words with internal stop closures like "algunas". (4) Valley snap made asymmetric outward-only (`direction="earlier"` for start, `"later"` for end) so the slot can only expand, never shrink inward and leave bonafide ghost. (5) **Removed time-stretch entirely.** Linear-interp resampling shifted pitch ("cartoony/grueso" artefact); replaced by natural-duration insert + `cumulative_offset_samples` to map original-bonafide positions onto current-result for W2/W3. (6) Crossfade redesigned to live at the SEAMS (not inside a fixed slot); cloned source extended by `cf` samples to land the fade in TTS silence padding around the word (prevents "Luga-" truncation). (7) Silent-run gate (`_silent_run_backward/_forward`) bounds the cloned-side extension so neighbouring cloned words do not leak into the seams. (8) `bonafide_start_s`/`bonafide_end_s` in `splice_metadata.json` now refer to positions in the SPLICED audio (where the spoof region lives) rather than original-bonafide coordinates, since the corpus only consumes per-word labels relative to the partial spoof WAV. Validation 2026-05-24 (12 cells, manifest mode): yield 151 -> 295 samples (1.95x), runtime 1h 8min, zero alignment-missing/seed-crash warnings, audit auditiva approved.
