Pipeline 01 — Mozilla Speaker Selection

Architecture

Selects acoustically-valid Spanish speakers from Mozilla Common Voice v24.0 and integrates them as new bonafide HABLA speakers — physically copied, renumbered in HABLA-style IDs, split 70/15/15.

01
Extract HABLA Embeddings
HablaEmbeddingExtractor · step_01_extract_habla_embeddings.py
Loads up to 20 audio samples per speaker from the 162 existing HABLA speakers. ECAPA-TDNN (192-dim, speechbrain/spkrec-ecapa-voxceleb). Per-speaker mean embedding, L2-normalized. Output: habla_embeddings.npy (162, 192)
02
Extract CV Embeddings
CVEmbeddingExtractor · step_02_extract_cv_embeddings.py
Parses CV v24.0 validated.tsv (436,590 rows). One ECAPA-TDNN embedding per candidate from their first validated sample. Output: cv_embeddings.npy (N_cv, 192)
03
Filter by Similarity
SimilarityFilter · step_03_filter_by_similarity.py
Full cosine similarity matrix CV @ HABLA.T → (N_cv × 162). Per CV speaker: take max_sim across all 162 HABLA speakers. Reject if max_sim ≥ 0.75. Output: filtered_speakers.json — 3,299 speakers pass.
04
Balanced Sampling
BalancedSampler · step_04_balanced_sampling.py
Stratified sampling across 5 accents and gender/age groups, targeting 15,340 total samples. Colombia and Chile top up existing HABLA counts. Mexico and Spain are entirely new accents. Output: selected_15340.tsv
05
Integrate CV Samples
DatasetIntegrator · step_05_integrate_cv_samples.py
Copies all 162 HABLA speakers into bonafide_dataset_by_speaker_v2/. Each new CV speaker gets a HABLA-style ID (e.g. mxm_00163). Split: 70% train / 15% val / 15% test. Handles both WAV and MP3 formats.

Pipeline 01 — Design Decision

Duplicate prevention

CV speakers have hashed client_ids — no overlap with HABLA-style speaker IDs. Speaker-ID matching is impossible. Acoustic similarity is used instead.

Three-step gate

01
HABLA reference embeddings
192-dim ECAPA-TDNN, averaged over ≤20 utterances per speaker, L2-normalized. Matrix: (162, 192).
02
CV candidate embeddings
Same ECAPA-TDNN model. One embedding per candidate from their first validated audio. Matrix: (N_cv, 192).
03
Cosine similarity gate
Full matrix CV @ HABLA.T → (N_cv × 162). Per CV speaker: max_sim across all 162. Reject if max_sim ≥ 0.75.

Code

# settings.py
SIMILARITY_THRESHOLD = 0.75

# step_03_filter_by_similarity.py
sim_matrix = cv_embs @ habla_embs.T
# shape: (N_cv, 162)

max_sim = sim_matrix.max(axis=1)
# one score per CV speaker

passed = max_sim < SIMILARITY_THRESHOLD
# must be distant from ALL 162
A CV speaker must be acoustically distant from every one of the 162 HABLA speakers — not just those from the same accent region.
Step 4 — Quality Validation

Rejection criteria

Every generated sample passes through a multi-layer validation gate in Step 4. Samples that fail any hard criterion are rejected and excluded from the final dataset. Two informational metrics (NISQA, ECAPA-TDNN similarity) are recorded but do not trigger rejection.

Hard rejection gates

01
Duration check
Audio length must be between 0.5s and 30s. Too short = truncated synthesis. Too long = hallucination loop.
02
Silence detection
No consecutive silence longer than 1 second. Catches synthesis failures where the model produces dead air mid-utterance.
03
WER — Word Error Rate
Transcribe with Parakeet TDT 0.6b-v3, compare to input text. Reject if WER > 15%.
WER = (S + D + I) / N
S = substitutions, D = deletions, I = insertions, N = reference word count
04
CER — Character Error Rate
Same Levenshtein distance but at character level. Reject if CER > 10%.
CER = (Sc + Dc + Ic) / Nc
Character-level edit distance — catches partial word mispronunciations missed by WER

Informational metrics (no rejection)

A
NISQA MOS
Non-intrusive perceptual quality score (1–5). Recorded for analysis — we track which pipelines produce the most natural-sounding audio.
B
ECAPA-TDNN Speaker Similarity
Cosine similarity between bonafide and synthetic embeddings (-1 to +1). Measures how well the TTS cloned the speaker's voice.
Why no similarity threshold? We deliberately do not reject on low similarity. Low-quality voice clones are still valid attack samples — a real anti-spoofing system must detect even poor impersonations.
ASR model: nvidia/parakeet-tdt-0.6b-v3 — multilingual Conformer-Transducer (25 languages including Spanish). Selected for its Spanish support over the English-only 1.1B variant.
Quality Metric — NISQA

NISQA: Non-Intrusive Speech Quality Assessment

A DNN-based model that predicts perceived speech quality without a clean reference signal — essential for evaluating TTS outputs where no "ground truth" audio exists for the target text.

Architecture

01
CNN feature extractor
Mel-spectrogram input → convolutional layers extract frame-level acoustic features.
02
Self-Attention pooling
Attention mechanism weighs frame importance — utterance-level representation without fixed-length constraint.
03
Regression head
Outputs a single scalar: Overall MOS (Mean Opinion Score) on a 1–5 scale.
We use only the overall MOS dimension. NISQA can predict 5 sub-dimensions (noisiness, coloration, discontinuity, loudness, overall), but for our pipeline we only record the overall MOS score — it captures the holistic quality judgment that matters for anti-spoofing dataset curation.

How we use NISQA

Role in pipeline
Informational only — no hard rejection threshold. Every Step 4 runs NISQA on each generated sample and stores the MOS score in validated_samples.json.

Quality Metric — ECAPA-TDNN

ECAPA-TDNN: Speaker Similarity

Measures how closely the synthetic audio matches the original speaker's voice. We use a pre-trained ECAPA-TDNN model to extract speaker embeddings, then compute cosine similarity between the bonafide reference and each generated sample.

Architecture

01
SE-Res2Net blocks
1D convolutional layers with Squeeze-and-Excitation and multi-scale Res2Net connections — captures speaker characteristics at multiple temporal resolutions.
02
Multi-layer Feature Aggregation
Concatenates outputs from all SE-Res2Net blocks — leverages both low-level acoustic features and high-level speaker information.
03
Attentive Statistical Pooling → 192-dim embedding
Attention-weighted mean + std pooling. Output: a single 192-dimensional L2-normalized speaker embedding vector.
Cosine similarity formula:
cos(a, b) = (a . b) / (||a|| x ||b||)
Range: -1 (opposite) to +1 (identical). Since embeddings are L2-normalized, this simplifies to a dot product.

How we use ECAPA-TDNN

Role in pipeline
Informational — no hard rejection. For each generated sample, we extract the speaker embedding and compare it to the bonafide reference embedding via cosine similarity. Stored in validated_samples.json.

SpeechGenerator · SpeechTrimmer
Chatterbox consistently generates loud noise (15–40% peak amplitude) after speech ends. Simple VAD or energy thresholds fail because the noise is too loud. The fix uses gap detection: find the longest silence gap in the second half, verify energy drops after it, trim at gap start + 150ms margin.
04
Validate Quality
QualityValidator
Multi-layer validation after trimming: duration · silence · Parakeet WER/CER · NISQA MOS · ECAPA-TDNN similarity.
05
Format Output
OutputFormatter
WAV → FLAC. ASVspoof2019 LA. System ID: CHATTERBOX. Audio IDs: LA_T_6000001+
Trailing noise trimmer — algorithm. (1) Smoothed RMS energy envelope: 25ms frames, 100ms rolling average. (2) Find silence gaps < 3% of peak amplitude, > 150ms duration. (3) Select the longest gap in the second half of audio. (4) Verify mean energy after gap < before gap — confirms noise, not speech. (5) Trim at gap start + 150ms margin. Safety: never trims more than 50% of audio length.
