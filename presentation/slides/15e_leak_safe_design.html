Augmentation — Design integrity

Augmenting without teaching the detector to cheat

Augmentation can quietly sabotage a detector: if anything about how a clip was processed correlates with its label, the network learns that shortcut instead of the spoofing artifact. We audited the pipeline and closed two such leaks, so — per the partial-spoof loudness work — the only signal that distinguishes bonafide from spoof is the synthesis itself.

Leak 1 — clean fraction
Balancing classes by augmenting one harder coupled "is it augmented?" to the label (12.5% vs 50% clean).

Fix: the same clean fraction for both classes (25% = 25%); class balance is handled separately, never via augmentation depth.
Leak 2 — loudness
Different augmentations left different loudness (clean = natural, codec = −20 dB), so level betrayed the augmentation type.

Fix: one uniform loudness normalization on every clip — clean and all augmentation types, every split — so level carries no information.
PropertyBefore (leaky)After (leak-safe)
Clean fraction per class bonafide 12.5% ≠ spoof 50% equal (25% = 25%)
Loudness by augmentation clean / codec / RIR all differ uniform −23 dBFS everywhere
RawBoost / Codec engines hand-rolled imitations official RawBoost + real ffmpeg codecs
Reverberation alignment centered (smeared / shifted) causal, direct-path aligned
Net effect. Augmentation is now label-blind: it does the same thing, with the same loudness and the same clean ratio, to bonafide and to every attack. A detector trained on this corpus cannot reach for "was this clip augmented?" — it has to learn what actually separates real speech from synthetic.
